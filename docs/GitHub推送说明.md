## 2. 标准推送流程

### 2.1 提交前检查

```bash
git status
git diff
git log -5 --oneline
```

### 2.2 暂存与提交

```bash
git add <文件或目录>
git commit -m "feat(scope): 简要说明本次改动目的"
```

提交信息建议遵循仓库既有风格，例如：

- `feat(key): …`
- `feat(inspect): …`
- `fix(…): …`

### 2.3 推送到 GitHub

首次推送当前分支（仅需一次）：

```bash
git push -u origin SVS_1.9.0
```

后续增量推送：

```bash
git push origin SVS_1.9.0
```

### 2.4 推送后同步更新本文档

每次向 GitHub 推送后，建议同步维护本文件，避免远程与本地记录不一致：

1. 在 **§3 近期推送摘要** 表格**顶部**追加本次 `git log -1 --oneline` 的提交哈希与简要说明。
2. 若新增或调整了 `docs/` 下其它文档，在 **§4 相关文档** 中补充链接。
3. 在 **§6 修订记录** 追加一行日期与变更说明。
4. 将上述修改与 `operatelog.md` 一并提交后再次执行 `git push origin SVS_1.9.0`。

示例（追加一行推送记录）：

```markdown
| `9c9e718` | 新增 GitHub 推送说明文档 |
```

### 2.5 网络异常时

若出现 `Could not connect to server` 或 `Connection was reset`，可在网络恢复后重试：

```bash
git push origin SVS_1.9.0
```

本地已提交但未推送时，`git status` 会提示 `Your branch is ahead of 'origin/SVS_1.9.0' by N commit(s)`。

## 5. 注意事项

1. **不要**在文档或提交中包含 `.env`、密钥、账号密码等敏感信息。
2. 原型改动除代码外，按项目约定同步更新 `operatelog.md`；涉及用户流程时同步 `docs/` 下对应文档。
3. 除 GitHub（`origin`）外，仓库可能配置了其他远程（如 Gitee）；推送前确认目标远程与分支名。
4. 合并到 `main` 或创建 Pull Request 前，建议在本地执行 `npm run dev` 验证界面可正常访问。
